## 0. 六条不可商量的纪律

1. **第一阶段不打分。**
   输出的是状态与事件，不是 0~100 的分数。一旦打分，会迅速退化成
   "看起来很科学、实际上参数高度自由"的技术指标。
2. **V0.1 参数冻结。**
   `config/dow_params.py::DOW_LITERAL_V01` 里的每个数值都必须能在书中找到出处，
   **不为回测效果做任何调整**。（唯一例外是 `filter_internal`，见下）
3. **不能因为某组指数回测最好就把它定成答案。**
   必须回答："如果换一组相近的市场指数，道氏信号还成立吗？"
4. **允许修结构 bug，不允许修参数。**
   V0.1 冻结期间只接受两类改动：
   - 让状态机**形式上更自洽**的修正（语义拆分、不变量、防前瞻偏差、
     结构定义的一致化）；
   - 修复逻辑错误。

   **不允许**为了改善 forward return / 年化 / Sharpe 而修改任何状态语义、
   数值参数、确认窗口或趋势定义。判断标准很简单：
   *这个改动能让"如果市场照原样再来一次，策略会更赚钱"吗？* 会，就拒绝。
5. **无前瞻必须可回归验证，不能靠人肉检查。**
   `tests/run_tests.py::test_engine_prefix_invariance` 是核心回归测试：
   对任意 t，「用全部数据跑出的 t 日状态」必须等于「只用截至 t 的数据跑出的
   最后一天状态」。它**不预设泄漏发生在哪个模块**，所以比逐个模块写针对性
   测试强得多 —— 修 `swing` / `confirmation` / `trend` / `secondary` / `line`
   任何一层之后都必须跑通。项目已经在这上面栽过两次
   （见第 5 节「确认日」型、第 6 节「极值日当可知日」型）。
6. **任何"降低了暴露"的改进，都必须配一个同暴露对照组。**
   "加了 Regime 之后回撤更小"几乎必然成立 —— 因为仓位更低了。不加对照组，
   随机空仓也会显得有效。标准做法：用**平均暴露完全相同、但常数缩放**的版本
   作对照。常数缩放**不改变 Sharpe**，所以对照组的 Sharpe 恒等于满仓版本，
   任何 Sharpe 差异都**只能**归因于时机选择。P11-C 严格执行了这条。

**任何回测与事件研究都必须遵守"信号在 t 日收盘产生、t+1 日生效"。**
这一条不是风格问题：本项目在前瞻偏差上吃过一次大亏 ——
修复前 RISK_ON 的次日照仓收益是 -7.65%，修复后同一策略是 +59.2%（详见第 5 节）。

关于唯一的非数值规则 `filter_internal`：3% 阈值必然产生"两端都被前一浪价格区间包含的内含微浪"。
如果拿它们比较高点低点，会得到"4741 比 4739 高 0.04% 所以仍是牛市"这种荒谬结论，
而市场其实早已跌破上一浪低点。汉密尔顿在图上永远比较**同一级别**的浪，
所以这里把内含浪丢掉。**它没有引入任何新的数字阈值**，只是一条结构规则。
（`trend_engine.filter_internal_swings` 的 docstring 里有完整的实例说明。）

## 2. 数据流

```
Index A (沪深300) ── Swing Engine ─┐
                                   ├── Confirmation Engine ──> Confirmed Swing
Index B (中证500) ── Swing Engine ─┘              │
                          ┌───────────────────────┼───────────────┐
                          ▼                       ▼               ▼
                   Trend Engine           Reaction Engine    Line Engine
                          └───────────────────────┼───────────────┘
                                                  ▼
                                          Volume Engine
                                                  ▼
                                            Dow Regime
```

每日输出（机器可读）：

```text
primary_trend        UP / DOWN / TRANSITION / UNCONFIRMED
trend_integrity      INTACT / DAMAGED / UNKNOWN   ← 当前趋势的结构是否还完好
reversal_candidate   NONE / BULL / BEAR           ← 结构已破但尚未确认的反转方向
last_confirmed_swing UP@2026-08-17
dual_confirmation    CONFIRMED / DIVERGENCE / NONE
secondary_reaction   NONE / ACTIVE / COMPLETED / OVERDUE / INVALIDATED
retracement_ratio    0.00 ~ 1.00（>1 表示已跌破本段行程起点）
secondary_duration   自然日
line_state           NONE / FORMING / ACCUMULATION / DISTRIBUTION
line_breakout        NONE / UP_CONFIRMED / DOWN_CONFIRMED / NO_CONFIRMATION
volume_state         HEALTHY / WEAK / EXHAUSTION
dow_signal           RISK_ON / RISK_OFF / WAIT
blocker              非 RISK_ON 时的首个阻断原因（归因用，P10.1）
```

> `primary_trend` 回答"历史上最后确认的主要趋势是什么"，
> `trend_integrity` 回答"这个趋势现在是不是还完好" —— 两者必须分开表达，
> 否则会混淆"牛市"与"牛市还没被破坏"。

信号只有三条硬规则，没有打分：

| 条件 | 信号 |
|---|---|
| trend=UP 且双指数确认 且 integrity=INTACT 且次级反应未 OVERDUE/INVALIDATED | RISK_ON |
| trend=DOWN 且双指数确认 且 integrity=INTACT | RISK_OFF |
| 其他（TRANSITION / 未确认 / 结构破坏 / 次级反应超期或失效） | WAIT |
| 线态向下突破 | 若当前 RISK_ON → 降为 WAIT（单边突破不确认） |

「结构 DAMAGED 就不得 RISK_ON」由**闸门**统一兜住，而不是把 trend 强行改成 DOWN ——
结构破坏要走完确认链（失败延续 → 结构破坏 → 确认 → 状态切换）。

## 5. ★ P10 结果：一个坏消息和两个真 bug

> 这一节是整个项目最重要的一节。**P10 的结论是负面的**，而且是刻意保留的负面结论。
>
> ⚠️ **本节数字处于"第一层前瞻已修、第二层前瞻未修"的状态。**
> P10.1 又查出并修复了第二层前瞻偏差（极值日 ≠ 可知日），修复后的数字见第 6 节 ——
> 两处**结论方向一致**（Dow 打不过 MA200），但具体数值以第 6 节为准。

### 5.1 两个真 bug（都已修复 + 回归测试）

**Bug 1 —— 前瞻偏差（严重，此前所有基线数字都受影响）**

第 12 章允许"另一指数稍后才确认"，所以 `confirm_primary` 会把一条浪标记为已确认，
即使确认它的另一指数浪是**几周甚至几个月之后**才走完的。
而引擎第一版按"本浪结束日"就把这条浪放进了结构 ——
等于在指数 A 的浪走完当天，就使用了指数 B 未来才给出的确认。

危害有多大？看这一对数字（同一个策略，唯一区别是持仓是否按 T+1 生效）：

| | 未平移 | T+1 生效（真实可交易） |
|---|---|---|
| 修复前 | +66.6% | **-7.65%** |
| 修复后 | +153.7% | **+59.2%** |

修复前，RISK_ON 精确地在阶段顶部亮起、又在下跌前一天熄灭 —— 这是典型的前瞻偏差特征。
修复方式：给 `ConfirmedSwing` 加 `available_date = max(本浪结束日, 确认浪结束日)`，
引擎一律按 `usable_date` 判断某条浪何时可以进入结构（`core/confirmation.py`、`core/regime_engine.py`）。
回归测试：`test_confirmation_has_no_lookahead`。

**Bug 2 —— 消融表的执行口径不一致**

`gate_positions` 返回当日仓位，但回测没有做 T+1 平移，
等于用当天收盘信号去吃当天收益。已统一为"信号收盘产生、次日生效"。

**另外修正两处语义/逻辑问题**：
- 消融变体 A 此前并非真正的"只有 HH/HL" —— 因为默认结构本身就是双指数确认后的浪构建的。
  现在引擎支持 `structure_source="index_a"`，A 变体真正只用指数 A 自己的浪。
- `TRANSITION` 子状态第一版里 T6 占了 90%：因为 `(H2>H1) != (L2>L1)` 恰好就是 TRANSITION
  的**定义**，用它判断"是否结构冲突"必然对 100% 的行成立。现改为按**变化幅度**分层。

### 5.2 坏消息：Dow V0.1 打不过一个 MA200

同口径（信号次日生效、单边 5bp、只做多、不加杠杆）：

| 策略 | CAGR | 最大回撤 | Sharpe | 持仓占比 | **持仓期年化** | 年换手 |
|---|---|---|---|---|---|---|

这套复杂结构，在只做多的口径下**没有跑赢一个简单的长期趋势滤波器**。

### 5.3 消融：每个附加闸门都在变差

### 5.4 所有变体共享同一个 -30% 回撤

A~F 六个变体的最大回撤**完全相同**（-30.0029%，2007-05-29 → 2007-07-05）。
原因是 2007 年"5·30"印花税突袭：所有变体当时都是满仓（trend=UP、结构完好、双指数确认、
无成线、无过热），而基于 3% 反向浪的结构对**单日政策冲击**没有任何反应速度。

含义：道氏结构能识别"趋势有没有变"，但不能防"一天之内政策变了"。这类风险必须由
执行层（仓位上限、波动率目标）解决，不该指望它。

### 5.6 P10 的结论

1. **Dow V0.1 作为一个交易策略是失败的**（跑不赢 MA200，更跑不赢 MOM120）。
2. **但它作为一个状态机是自洽的**：不变量 0 违规，RISK_ON/RISK_OFF 的条件收益方向正确。

## 6. ★ P10.1 审计：第二层前瞻偏差、12% 持仓归因、子状态稳健性

> P10 修掉的是「确认日」型前瞻（`available_date` 用了确认浪的结束日）。
> P10.1 用**一个不预设泄漏点的测试**，又抓出了**第二类**前瞻偏差，
> 并顺带回答了「12% 的持仓到底是怎么来的」。

### 6.1 Prefix Invariance：不预设泄漏点的审计

对任意历史日期 `t`，如果引擎在 `t` 日没有使用 `t` 日之后的信息，那么必须成立：

```text
用全部数据跑出的 t 日状态  ==  只用截至 t 的数据跑出的最后一天状态
```

它的价值在于**不预设泄漏发生在哪个模块**：swing / confirmation / trend /
secondary / line / volume / regime，任何一层的未来函数都会被同一次比对抓住。

**结果：修复前，36 个审计点里 21 个不一致（58%）。** 指纹极其清晰：

```text
2008-09-23   full='DOWN@2008-09-23'   prefix='UP@2008-09-22'
2009-07-29   full='DOWN@2009-07-29'   prefix='UP@2009-07-28'
```

`full` 里存在一条**极值日正好等于 `t`** 的浪，而 `prefix` 里它根本不存在。

### 6.2 根因：极值日 ≠ 可知日

`detect_swings` 里 `add()` 记录的 `end_date` 是**极值点当天**，但这条浪要到价格
从极值**反向走够 3%** 之后才会被创建出来：

```text
高点在 3/01  →  直到 3/20 跌够 3%，这条上升浪才被识别出来
```

而 `ConfirmedSwing.available_date = max(本浪结束日, 确认浪结束日)` 用的全是极值日，
**完全没有体现这个识别延迟**。于是引擎在 3/01 当天，就用上了 3/20 才知道的浪。

修复清单（全部属于「修结构 bug」，**没有动任何数值参数**）：

| 位置 | 改动 |
|---|---|
| `Swing.detected_date` | 新增：这条浪被识别的日期（反向走够阈值的那天） |
| `Swing.known_date` | 新增 property `= detected_date or end_date` |
| `confirm_primary` | `available_date = max(本浪 known_date, 确认浪 known_date)`；未确认时 = 窗口关闭的**可知**时点；窗口至今未关闭（后面再没有更多浪）= `date_max()`（永远不可用） |
| 确认匹配 | 新增约束「确认浪必须在窗口关闭之前就被识别」（`o.known_date <= window_close_known`），并取**最早被识别**的匹配浪而非第一条 |
| 窗口上界 | 价格上界仍用 `next.end_date`（经济语义），但「窗口关闭」的可知时点用 `next.known_date` |
| provisional 浪 | 彻底踢出确认判定 —— 旧代码那句 `if s.end_date is not None` 是 no-op，开放浪一直在参与 |

**修复后：5 个指数配对 × 61 个审计点 = 305 个点，全部一致。**

已固化为**核心回归测试** `test_engine_prefix_invariance`：以后修改
`trend_engine` / `secondary_reaction` / `line_detector` / `confirmation`
都必须先通过它。

### 6.3 这个修复对 P10 结论的影响

| | 修复前 | 修复后 |
|---|---|---|
| Dow 引擎实际信号 CAGR | 2.2% | **4.17%** |
| Sharpe | 0.29 | **0.534** |
| 最大回撤 | -30.0% | **-26.5%** |
| 持仓占比 | 12.4% | 11.7% |
| MA200（基准） | 11.1% / 0.68 | 11.12% / 0.682 |

**方向没变：Dow 仍然打不过 MA200。** 但数字变好了 —— 这与第一层前瞻
（修复后 +66.6% → -7.65%，**变差**）方向相反。值得记住的规律：
**修前瞻不一定让结果变差，但一定会让结果变得可信。**

### 6.4 空仓归因：12% 是「道氏本来就稀疏」还是「实现规则过严」？

对每个非 RISK_ON 交易日记录**首个阻断原因**（按原书闸门顺序：有没有趋势 →
结构 → 确认 → 位置 → 线）：

| 阻断原因 | 天数 | 占空仓 | 段数 | 平均段长 | fwd60 均值 | fwd60 胜率 | MFE/MAE |
|---|---:|---:|---:|---:|---:|---:|---:|
| TRANSITION | 2919 | 62.6% | 25 | 116.8 | +2.97% | 50.6% | 1.43 |
| TREND_DOWN | 1080 | 23.2% | 11 | 98.2 | -2.16% | 41.7% | 0.76 |
| STRUCTURE_DAMAGED | 544 | 11.7% | 21 | 25.9 | +5.48% | 53.4% | 1.82 |
| SECONDARY_OVERDUE | 73 | 1.6% | 3 | 24.3 | +5.91% | 95.9% | 2.59 |
| NO_TREND_UNCONFIRMED | 21 | 0.5% | 1 | 21.0 | -3.11% | 19.0% | 1.29 |
| NO_DUAL_CONFIRMATION | 19 | 0.4% | 1 | 19.0 | +24.69% | 100% | 10.01 |
| LINE_DOWN_OVERRIDE | 4 | 0.1% | 4 | 1.0 | +5.22% | 100% | 11.94 |

**结论：12% 的持仓主要是道氏理论固有的，不是实现 bug。**

- **85.8% 的空仓来自 TRANSITION(62.6%) + TREND_DOWN(23.2%)** —— 两者都是理论的
  核心设计，而且统计上**挡得对**：TRANSITION 的 MFE/MAE 只有 1.43、胜率 50.6%

- `SECONDARY_OVERDUE` 看起来最「可惜」（胜率 95.9%、MFE/MAE 2.59），
  但只有 **73 天 / 3 段**，样本远不足以支撑任何结论。

### 6.5 闸门解除敏感性（诊断，**不是**策略）

从 Base 出发，每次只撤掉一道闸门：

| 变体 | 暴露（沪深300+中证500） | vs Base | fwd60 质量 |
|---|---:|---:|---|
| Base = 引擎实际 RISK_ON | 11.73% | — | +8.64% / 74.3% |
| 撤掉次级反应闸门 | 13.09% | +72 天 | +8.35% / 76.6% |
| 撤掉线态向下否决 | 11.80% | +4 天 | +8.62% / 74.5% |
| 撤掉双指数确认要求 | 12.09% | +19 天 | +9.12% / 75.1% |
| 撤掉结构完好要求（integrity） | 11.73% | **+0 天** | 同 Base |
| 把 TRANSITION 也当作可入场 | 11.73% | **+0 天** | 同 Base |

**没有任何单一闸门是市场暴露的瓶颈** —— 撤掉任何一道，暴露最多从 11.73% 到 13.09%。

两个结构性发现：

1. **`integrity == "INTACT"` 在信号判定里是冗余的。** 对 UP 趋势
   `DAMAGED` ⟺ `INVALIDATED`（两者共用同一个参照点，这就是 INV-02），
   而 `not blocked` 已经蕴含 `not INVALIDATED`，这道闸门被次级反应闸门完全吸收。
   实测：UP & DAMAGED 的 544 天里，**544/544 全部是 INVALIDATED**。
   （保留它作为显式表达仍有可读性价值，但不要以为它是一道独立闸门。）
2. **次级反应闸门是唯一「撤掉后质量下降」的闸门。** 在「上证+深证」配对上，
   撤掉它多出 214 天暴露，但 fwd60 从 10.86% 掉到 5.66%、胜率从 66.3% 掉到 50.0%。
   它是真的在挡东西。

**结论：不能把任何 TRANSITION 子状态改成 RISK_ON。** 「T2/T3 有正收益」只在

### 6.7 P10.1 的结论

## 8. ★ P11：换一个问题 —— Dow 作为**组合 Regime 层**有没有增量价值

P10 问的是"Dow 自己能不能赚钱"，答案是不能。P11 把问题换成：

> **当已经存在一个股票 Alpha 之后，Dow Regime 能不能改善整个组合的风险收益结构？**

这是完全不同的问题，也是 Dow 真正应该接受的考验 —— 它不再是交易系统，
而是一个 **Market Regime Engine 候选**。

### 8.1 P11-A/B：时间稳定性（`out/p11_stability*.md`）

**最重的一条负面结论：信息含量高度集中在 2005-2010。**

| 区间 | RISK_ON − WAIT (fwd60) | RISK_OFF − WAIT (fwd60) |
|---|---:|---:|
| 2005-2010 | **+9.6pp** | **−21.3pp** |
| 2011-2015 | （RISK_ON 未出现） | −3.0pp |
| 2016-2020 | **−1.7pp** | −9.5pp |
| 2021-2026 | +4.1pp | **−0.9pp** |

全样本看，RISK_ON 的 fwd60 比 WAIT 高 5.7pp（8.64% vs 2.94%），很漂亮。
但拆到区间就现出原形：**RISK_OFF 的避风价值从 −21.3pp 衰减到 −0.9pp**。

逐年看更清楚（基准用同年 WAIT，因为 RISK_ON / RISK_OFF 是**按年交替**的状态，
同一年内极少共存，"同年价差"多数年份根本算不出来）：

- pair0（沪深300+中证500）：RISK_ON 优于同年 WAIT 的只有 **2/9 年**。
  2007 年 RISK_ON 的 fwd60 是 +17.0%，而同年 WAIT 是 **+22.9%** ——
  **确认让人在牛市里晚进场。**
- 换一组配对（上证+深证）：UP>DOWN 只在 **1/4** 个区间成立，
  5 年滚动价差为正的比例只有 **54.2%**（pair0 是 92.4%）。
- RISK_ON 在 22 年里只亮了 **9 年**，其中 266/619 天集中在 2007 + 2009。

所以：**"用哪个指数配对"和"看哪段时间"，都强烈影响结论** —— 这本身就是
不稳定性指标，而不是"再调一下就好"的问题。

### 8.2 P11-C：组合覆盖层（`out/p11_overlay*.md`）

Alpha = 最简单的横截面动量（120 日收益取前 30 等权、20 日调仓、T+1 成交、
单边 12bp），**刻意不含 PA**。股票池 HS300 非ST 280 只（279 只可用），
样本 2005-01 ~ 2026-09。

| 策略 | CAGR | Sharpe | MaxDD | 平均暴露 |
|---|---:|---:|---:|---:|
| Alpha（满仓） | 7.19% | 0.379 | −76.5% | 93.9% |
| 基准：等权全池 | 16.98% | 0.721 | −72.5% | — |
| **MA200 择时（参照）** | 11.74% | 0.587 | −48.6% | 53.9% |
| Dow M1_示意(1/.5/.2) | 8.20% | 0.495 | −41.5% | 56.2% |
| Dow M2_只避下跌 | 13.51% | **0.589** | −54.0% | 73.5% |
| 等暴露对照 M1（不择时） | 5.26% | 0.379 | −53.1% | 56.2% |

**结论有两条，必须一起看：**

1. **Dow 的择时不是"仓位变低"的假象。** 对照组是**同平均暴露的常数缩放**，
   它的 Sharpe 恒等于满仓 Alpha 的 0.379（常数倍缩放不改变收益/风险比）。
   Dow 在 6 组映射里有 **5 组**把 Sharpe 抬到 0.400~0.589。
   这说明 Dow 的**时机**本身确实携带信息。
2. **但没有任何 Dow 映射能稳定超过 MA200。** MA200 参照的 Sharpe 增益是 **0.208**，
   6 组 Dow 映射里只有 **1 组**超过它（换成上证+深证配对是 **0/6**）。
   最好的 Dow 映射（M2，Sharpe 增益 **0.210**）**刚好追平** MA200。
   > **Dow 提供的风险控制，一根免费的 200 日均线就能做到。**

分区间看，Dow 的贡献同样不稳：M1 在 2005-2010 把 CAGR 从对照组的 6.39% 提到
17.50%，2021-2026 从 3.43% 提到 7.47%，但在 **2011-2015 是 −3.98% vs 对照组 +0.47%**。

### 8.3 P11 的结论

**Dow Regime V0.1 作为组合风险控制变量：有方向性增量，但没有不可替代性 ——
它不优于一个 200 日均线。** 这与 P10 的结论一致，只是换了一套更严格的口径
（同暴露对照 + MA200 参照）重新验了一遍。

因此 **V0.1 正式冻结**，不再优化。项目重心转入 **P12 Alpha Discovery**：

- 本次的"最简单动量"在 A 股**跑输等权**（7.19% vs 16.98%，Sharpe 0.379 vs 0.721），
  横截面动量在 A 股本就偏弱/易反转（已知现象，不是本次实现的 bug）。
- 所以真正决定收益的是 **Alpha 层**，而不是 Regime 层。
  Dow 该被放在"组合风险控制变量"的位置上，而不是"收益来源"的位置上。

> **P11 踩到并堵住的两个口径陷阱（写在这里防复发）**
>
> - **两腿的时间窗必须相同。** 个股数据比指数长（可回溯到 1991 年），
>   不裁剪就会变成"Alpha 跑 1991-2026、Dow 跑 2005-2026"的错位比较。
> - **`close = 0` 不是价格。** 新浪用 0 标记停牌，不处理会产生 −100% 的单日收益
>   （实测最低单日 **−1650%**），再顺着权重漂移 `w*(1+r)/denom` 把权益曲线打穿。

## 9. 待办 / 已知问题

- [x] ~~**持仓占比只有 12% 是最大的问题**~~ → **P10.1 已归因完成**：
      85.8% 来自 TRANSITION + TREND_DOWN（理论核心设计，且统计上挡得对），

      定义」（例如 `ref_low = max(leg_origin, L2)` 取更严格一侧是否过保守）——
      这是**规则语义研究**，不是调 3% 这类数值参数。
- [ ] `integrity == "INTACT"` 在信号判定中是**冗余条件**（被次级反应闸门完全吸收，
      实测 UP & DAMAGED 的 544 天 100% 是 INVALIDATED）。保留是为了可读性，
      但必须在文档里说明，避免以后被误当成一道独立闸门去调。
- [ ] `SECONDARY_OVERDUE` 只有 73 天 / 3 段（fwd60 胜率 95.9%、MFE/MAE 2.59），
      样本远不足以判断它是否真的「挡错了」。需要更多指数配对或更长样本。
- [ ] TRANSITION 子状态收益**跨指数配对完全不稳定**（T4 从 -1.15% 变 +11.56%，
      T3 从 +2.40% 变 -6.87%）。P11 walk-forward 必须把「子状态收益排序」
      本身当作不稳定性指标报出来，而不是只报某一组的数字。
- [ ] `PAIR_MODEL(A/B)`（Sharpe 0.58）是目前最好的 Dow 类策略，但它靠的是
      "RISK_ON 持沪深300 / 否则持中证500"的资产切换，需要单独检验这个切换本身
      是否只是中小盘 beta 的暴露。
- [ ] `secondary_duration` 目前是自然日，应改为交易日（需交易日历）。
- [ ] 沪深300 在 2002~2005 早期有 721 天成交量为 0，量价模块会输出 INSUFFICIENT_DATA。
- [ ] `T1_just_lost_trend` 与 `T5_line_forming` 在实测中几乎不出现（优先级的副作用），
      需要检查它们的判据是否被其他条件遮蔽。
- [ ] **A 股执行层**（涨跌停、停牌、ST、T+1、滑点、税费）必须与 Dow Engine
      完全分离，尚未建立。P11-C 证明了没有它收益会被系统性高估，优先级已上调。
- [ ] **P11-C 的生存偏差**：股票池是*今天*的 HS300 成分回溯到 2005 年，
      免费源拿不到 point-in-time 成分股，绝对收益被高估。缓解理由是同暴露
      对照组与 MA200 参照**共享同一偏差**，所以"增量"结论受影响小 ——
      但**绝对收益**（Alpha 7.19%、等权 16.98%）不可当真。
- [ ] **横截面动量在 A 股跑输等权**（7.19% vs 16.98%）。这不是实现 bug，
      而是"最简 Alpha 在 A 股偏弱/易反转"这一已知现象。P12 必须正面回答
      "什么样的 Alpha 才值得往上叠 Regime"，而不是接着优化 Regime。
- [ ] **Dow 的 Regime 结论对"配对"和"时段"都敏感**（pair0 滚动正 92.4%
      vs pair1 54.2%）。任何要发布的应用都必须**绑定一个具体配对**并声明这一点，
      不能只说"道氏状态"。
- [ ] `ref_low = max(leg_origin, L2)` 是否过保守 —— 仍是有效的**规则语义**问题，
      但已被 P11 降级为非主线：即使把暴露提上去，状态的信息含量衰减
      （1b 节）也不会因此改善。
